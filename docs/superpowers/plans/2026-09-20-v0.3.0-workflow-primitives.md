## Thesis

The v2.0 book positions SNAIL as "the deterministic workflow primitive set" — chaining + routing + parallelization, all with OOD-as-type. v0.2.3 ships chaining and routing in a primitive way, parallelization as an afterthought (the user has to hand-wire multiple nodes with shared inputs), and there is no first-class "OOD escalates to a heavier node" primitive.

v0.3.0 closes those three gaps. After this release, the workflow primitive set is complete: chain, route, escalate, parallel. The book stops making claims the codebase can't keep.

## Three primitives, three milestones

### M1 — Escalation primitive (`escalate`)

**Goal:** Make `OOD → heavier node` a one-liner instead of hand-wired edges.

**API shape (proposed, may iterate during impl):**

```python
from snail import escalate, edge, Program, HostedNode

# Tier 1: small fast model
classify_intent_small = HostedNode(
    name="classify_intent_small",
    output_schema=Intent,
    endpoint="anthropic://claude-haiku-4-5",
    confidence_threshold=0.7,
    distribution="customer_intents_v3_tier1",
    cost_tier="small",
)

# Tier 2: bigger model, only invoked on OOD from tier 1
classify_intent_large = HostedNode(
    name="classify_intent_large",
    output_schema=Intent,
    endpoint="anthropic://claude-sonnet-5",
    confidence_threshold=0.85,
    distribution="customer_intents_v3_tier2",
    cost_tier="large",
)

program = Program(
    name="intent_with_escalation",
    nodes=[classify_intent_small, classify_intent_large, downstream_node],
    edges=[
        escalate(classify_intent_small, to=classify_intent_large),  # auto: OOD → large; OK → downstream
        edge(classify_intent_small.ok, target_field="intent"),     # user keeps control of OK routing
        edge(classify_intent_large.ok, target_field="intent"),     # and large's OK routing
        # OOD from large → fallback node, NOT back to small (no loops)
    ],
)
```

**Behavior:**
- `escalate(node, to=other)` automatically adds `edge(node.ood, target_field=<other's input>)`.
- The escalated `to` node must already exist in `Program.nodes` (no implicit node creation).
- Rejects circular escalation at composition time (raises `ProgramValidationError`).
- Rejects escalating to a node with lower declared `cost_tier` (no cheapening).

**File layout:**
- `src/snail/escalation.py` — `escalate()` helper, `CostTier` enum, validation logic
- `src/snail/__init__.py` — re-export `escalate`, `CostTier`
- `src/snail/program.py` — minor: surface the validation error class

**Tests:**
- `tests/test_escalation.py`:
  - `test_escalate_basic_ok_routing` — escalation wires OOD correctly
  - `test_escalate_basic_ood_routing` — escalation wires OOD correctly
  - `test_escalate_rejects_unknown_target` — `to=` node not in nodes list → raises
  - `test_escalate_rejects_cycle` — A.escalate(B).escalate(A) → raises
  - `test_escalate_rejects_downgrade` — `cost_tier` downgrade → raises
  - `test_escalate_manifest_records_path` — manifest records which tier produced each output

### M2 — Cost/token accounting in Manifest

**Goal:** Every node records what it cost. The manifest becomes a cost ledger.

**API shape (additive, no breaking changes):**

```python
# Per-node addition to Manifest.node_invocations:
{
    "node_name": "classify_intent_small",
    "input_hash": "...",
    "output_hash": "...",
    "ok_or_ood": "ok",
    "started_at": "...",
    "ended_at": "...",
    "latency_ms": 412,
    # NEW:
    "tokens_in": 845,
    "tokens_out": 23,
    "cost_usd": 0.000168,
    "model_id": "claude-haiku-4-5@2026-07-15",
}

# Top-level Manifest addition:
{
    ...
    "summary": {
        "total_tokens_in": 8420,
        "total_tokens_out": 312,
        "total_cost_usd": 0.002341,
        "nodes_fired": 5,
        "escalations_triggered": 1,
    }
}
```

**How providers report cost:**
- `anthropic` provider: returns `usage.input_tokens` + `usage.output_tokens` from Messages API response; cost from per-model pricing table (hardcoded for the supported models — `claude-haiku-4-5`, `claude-sonnet-4-5`, `claude-sonnet-5`, `claude-opus-5`).
- `openai_compat`: returns `usage.prompt_tokens` + `usage.completion_tokens`; cost from per-model pricing (small initial table — GPT-5, GPT-5 mini; users can override via `cost_per_1k_tokens_input` / `cost_per_1k_tokens_output` kwargs).
- `ollama`: cost = 0 (local).
- `stub`: cost = 0.

**Provider API change:**

```python
class Provider(Protocol):
    def complete(self, request: CompletionRequest) -> CompletionResponse: ...

# NEW: CompletionResponse gains:
@dataclass
class CompletionResponse:
    text: str
    raw: dict  # original provider response, for telemetry
    # NEW:
    tokens_in: int = 0
    tokens_out: int = 0
    model_id: str = ""
```

### M3 — Parallel fan-out primitive (`parallel_edges`)

**Goal:** Multiple nodes run on the same input, results merge in a join node. No back-edges.

**API shape:**

```python
from snail import parallel_edges, edge, Program

# Three extractors run in parallel on the same input
extract_email = HostedNode(name="extract_email", output_schema=Email, ...)
extract_phone = HostedNode(name="extract_phone", output_schema=Phone, ...)
extract_address = HostedNode(name="extract_address", output_schema=Address, ...)

# Join node receives all three results as a single dict
merge = DeterministicNode(
    name="merge",
    fn=lambda ctx, email_result, phone_result, address_result: Contact(
        email=email_result.value,
        phone=phone_result.value,
        address=address_result.value,
    ),
    output_schema=Contact,
)

program = Program(
    nodes=[extract_email, extract_phone, extract_address, merge],
    edges=[
        parallel_edges(
            inputs=raw_input_node,
            to=[extract_email, extract_phone, extract_address],
        ),
        edge(extract_email.ok, target_field="email_result"),
        edge(extract_phone.ok, target_field="phone_result"),
        edge(extract_address.ok, target_field="address_result"),
    ],
)
```

**Behavior:**
- `parallel_edges(inputs=node, to=[list_of_nodes])` declares that all `to` nodes receive the same input from `inputs`.
- The runner executes them in parallel (asyncio.gather under the hood, since all providers are async-friendly or wrapped).
- Sequential execution is the fallback for non-async nodes.
- The merge / join node is a normal downstream node that takes each parallel node's OK payload as separate typed inputs.

**File layout:**
- `src/snail/parallel.py` — `parallel_edges()` helper
- `src/snail/program.py` — `Program.run()` gains parallel-execution branch
- `src/snail/runner.py` — NEW: extracted runner with parallel/sequential logic

## Out of scope for v0.3.0

- Real distillation-based trainer (multi-week, GPU, eval harness)
- Real `weight_pin` verification (needs real frozen weights from a real trainer)
- Confidence calibration tooling (`snail calibrate` CLI)
- MCP integration
- Streaming execution with incremental manifest updates

These are v0.4.0+ candidates.

## Risk register

| Risk | Mitigation |
|---|---|
| `escalate()` API shape doesn't match user mental model | Land M1 first, get user feedback before locking M2/M3 |
| Cost tables go stale on provider pricing changes | Make pricing a module the user can override; document the override |
| Parallel execution breaks a provider that isn't truly async | Default to sequential; only opt into parallel when provider declares it's safe |
| Manifest schema change breaks back-compat for v0.2.x users | Additive-only changes (new fields), no removed fields. Document in CHANGELOG |
