## Thesis

v0.3.0 completed the workflow primitive set (chaining + routing + parallel). v0.4.0 closes the loop on **the two audit claims the v2.0 book makes but the v0.3.0 codebase cannot keep**:

1. **"Frozen and hash-verified."** Today `weight_pin: phi-4-mini-3.8b@sha256:placeholder` is illustrative; no actual hash check happens at construction or runtime. After v0.4.0, `Program(...)` with a node whose loaded weights file doesn't match the pinned SHA-256 raises `WeightPinMismatch` immediately — and `Program.run()` does the same when the manifest records the hash for a real call.

2. **"Confidence is calibrated."** Today `_extract_confidence(result.ok)` reads whatever the model said, with no check that `0.7` confidence actually means ~70% accuracy. After v0.4.0, `snail calibrate` CLI runs the program's golden cases, plots confidence-vs-accuracy, and emits a `CalibrationReport` JSON the user can gate the deployment on.

These are the two pieces that turn SNAIL from "well-typed pipeline DSL" into "auditable discipline." They are also the deliverable that justifies calling this an `anti-agentic` framework rather than a typedef library.

## Two milestones

### M1 — Real `weight_pin` SHA-256 verification

**Goal:** `weight_pin: "phi-4-mini-3.8b@sha256:<hex>"` is enforced at construction AND at run time.

**Format (unchanged from v0.2.0):**
```
<model_name>@sha256:<64-hex-chars>
```

**Behavior:**
- `Program(..., strict_mode=True)` (default) reads each `@node`-decorated function's `frozen_weights` path. If the path exists, the program computes its SHA-256. If the path doesn't exist, the node is treated as "no weights to verify" — but if a `weight_pin` IS declared and no weights file exists, raise `WeightPinMismatch`.
- When a node has both a `weight_pin` and a `frozen_weights` path that exists, the program's `_validate()` compares the computed SHA-256 to the pin. Mismatch → `WeightPinMismatch`.
- When `Program.run()` fires the node, the manifest entry records the SHA-256 it actually loaded. If the runner re-loads and gets a different hash, it raises.

**File layout:**
- `src/snail/weights.py` — NEW: `compute_sha256(path)`, `parse_weight_pin(pin)`, `verify_weight_pin(pin, actual_path)`, `WeightPinMismatch` exception
- `src/snail/errors.py` — NEW: top-level `SNAIL` exception namespace
- `src/snail/program.py` — add weight-pin verification step in `_validate()`
- `src/snail/__init__.py` — re-export `compute_sha256`, `verify_weight_pin`, `WeightPinMismatch`

**Tests (`tests/test_weight_pin.py`):**
- `test_parse_weight_pin_valid`: parses `"phi-4@sha256:abc..."`
- `test_parse_weight_pin_rejects_missing_hash`: `"phi-4@sha256:"` → raises
- `test_parse_weight_pin_rejects_wrong_format`: `"phi-4@sha3:abc"` → raises
- `test_compute_sha256_matches_known_value`: known input → known SHA-256
- `test_verify_weight_pin_match`: pin matches file → no exception
- `test_verify_weight_pin_mismatch`: pin doesn't match → `WeightPinMismatch`
- `test_program_rejects_mismatched_pin`: `Program(...)` with bad pin → `WeightPinMismatch`

### M2 — `snail calibrate` CLI + confidence-vs-accuracy tooling

**Goal:** Trustworthy confidence, not just plausible confidence.

**CLI surface:**
```bash
snail calibrate PROGRAM_PATH \
    --golden-dir goldens/golden \
    --output report.json \
    --plot report.png
```

**Behavior:**
- Loads a `Program` and runs every golden case in `--golden-dir` against it.
- For each case, records: input, expected output, predicted output, predicted confidence, accuracy (1 if predicted matches expected, 0 otherwise).
- Computes:
  - **ECE** (Expected Calibration Error) over 10 confidence bins — the canonical calibration metric.
  - **Per-bin accuracy** — array of (bin_low, bin_high, count, accuracy, avg_confidence).
- Writes `report.json` (machine-readable) and `report.png` (matplotlib reliability diagram).
- Exit 0 if ECE < threshold (default 0.10); exit 1 otherwise.

**File layout:**
- `src/snail/calibrate.py` — NEW: `run_calibration(program, golden_dir) -> CalibrationReport`, `compute_ece(...)`, `plot_reliability_diagram(...)`
- `src/snail/cli.py` — add `calibrate` subcommand
- `src/snail/__init__.py` — re-export `run_calibration`, `CalibrationReport`

**Tests (`tests/test_calibrate.py`):**
- `test_calibrate_perfect_model_ece_zero`: synthetic golden cases where confidence == accuracy → ECE = 0
- `test_calibrate_overconfident_model_high_ece`: confidence always 0.95 but only 50% accurate → ECE > 0.3
- `test_calibrate_underconfident_model_high_ece`: confidence always 0.5 but always accurate → ECE > 0.3
- `test_calibrate_emits_report_json`: run_calibration writes a valid JSON file
- `test_calibrate_cli_exit_zero_on_perfect`: CLI exits 0 when ECE below threshold
- `test_calibrate_cli_exit_one_on_overconfident`: CLI exits 1 when ECE above threshold

## Out of scope for v0.4.0

- Real distillation-based trainer (multi-week, GPU, eval harness)
- MCP integration
- Streaming execution with incremental manifest updates
- Confidence-binning parameterization (always 10 bins in v0.4.0)

These are v0.5.0+ candidates.

## Risk register

| Risk | Mitigation |
|---|---|
| Weight-pin check breaks existing tests that use illustrative pins | Existing v0.2.x/`Example`s that pin to `phi-4-mini-3.8b@sha256:placeholder` will now fail at construction. Plan: tests that exercise `weight_pin` will point at real (test-fixture) weights files; documentation will deprecate the `placeholder` value. |
| `snail calibrate` matplotlib dependency is heavy | matplotlib is already an optional dependency via `pyproject.toml`'s extras; document `pip install snail-dsl[calibrate]` for users who want plotting. |
| ECE computation edge cases (empty bins) | `compute_ece` skips empty bins in the denominator; tested with synthetic edge cases. |
